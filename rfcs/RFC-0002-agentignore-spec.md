# RFC-0002: .agentignore File Specification v1

**Author:** John Bejenariu

**Status:** Draft
**Relates to:** P2.05, P2.04, P1.03
**Repo:** `prontiq/ariscan`

## Summary

Defines `.agentignore` — a file format for declaring paths, patterns, and file categories that AI coding agents should deprioritize or exclude from their context window. The format follows `.gitignore` syntax conventions for developer familiarity while adding agent-specific semantics.

## Motivation

AI coding agents ingest repository context to understand codebases before making changes. However, not all files are equally valuable:

- **Generated files** (lockfiles, build output, bundled vendor code) consume tokens without adding decision-relevant information
- **Binary assets** (images, fonts, compiled artifacts) waste context budget entirely
- **Large data fixtures** and test snapshots add noise that degrades reasoning quality
- **Sensitive paths** (credentials, internal configs) should be excluded for security reasons

Research shows context volume alone degrades agent reasoning (Liu et al. 2024 — >30% degradation from mid-context placement; Context Length Hurts 2025 — volume degrades reasoning). The `.agentignore` file gives teams a declarative, versionable way to optimize what agents see.

**Goal:** `.agentignore` becomes as standard as `.gitignore` — every repository has one.

## Design

### File Location and Discovery

- Primary: `.agentignore` at repository root
- Additional: `.agentignore` files in subdirectories (scoped to that subtree)
- Inheritance: subdirectory files extend (not replace) parent rules
- Config override: `ariscan.yml` can specify alternative ignore file paths

### Syntax

Follow `.gitignore` conventions exactly:

```
# Comments start with hash
# Blank lines are ignored

# Standard glob patterns
*.lock
*.min.js
*.min.css
dist/
build/
node_modules/
vendor/

# Negate patterns with !
!package-lock.json

# Directory-only patterns end with /
__pycache__/
.next/
.nuxt/

# Double-star for recursive matching
**/fixtures/**
**/snapshots/**
**/*.generated.*
```

### Agent-Specific Extensions

Beyond standard gitignore patterns, `.agentignore` supports optional category annotations:

```
# @category: generated
dist/
build/
*.generated.*
*.compiled.*

# @category: data
**/fixtures/**
**/testdata/**
**/__snapshots__/**

# @category: binary
*.png
*.jpg
*.gif
*.woff2
*.ttf

# @category: vendor
vendor/
third_party/
node_modules/

# @category: sensitive
.env*
**/credentials/**
**/secrets/**
```

Categories enable:
- Per-category token budget reporting in `ariscan`
- Category-level override in `ariscan.yml` policy
- Agent-specific category handling (some agents may want test fixtures, others don't)

### Interaction with Other Ignore Files

| File | Relationship |
|---|---|
| `.gitignore` | Independent. Files in `.gitignore` are often also in `.agentignore`, but not always (e.g., lockfiles are tracked by git but noisy for agents) |
| `.dockerignore` | Independent. Different purpose (build context vs agent context) |
| CODEOWNERS | Complementary. CODEOWNERS defines ownership; `.agentignore` defines agent relevance |
| `.cursorignore` | Superset intent. `.agentignore` is agent-agnostic; Cursor-specific ignores can be derived from it |

### Scoring Impact

The presence and quality of `.agentignore` affects ARI scoring:

- **P1 (Context Quality):** Reduces noise in agent context, improving additionality scores
- **P5 (Machine Readability):** Structured exclusion signals improve doc-to-noise ratio
- **P7 (Navigability):** Excluding irrelevant paths reduces agent navigation burden

Scoring criteria for `.agentignore` quality:
1. **Exists** — file present at repo root (+base points)
2. **Non-trivial** — contains meaningful patterns beyond defaults (+quality points)
3. **Categorized** — uses category annotations for structured exclusion (+bonus points)
4. **Maintained** — patterns match actual repo structure, no stale entries (+maintenance points)
5. **Budgeted** — estimated token savings are meaningful relative to repo size (+impact points)

## Implementation Plan

1. **Parser implementation** — gitignore-compatible parser with category annotation support
2. **Discovery integration** — add `.agentignore` to context file discovery (P1.03)
3. **Scoring rules** — implement quality criteria in Context Quality pillar
4. **Token budget integration** — connect to context budget analyzer (P2.04)
5. **Template generator** — language/framework-aware defaults in `--fix` command
6. **Documentation** — specification page on prontiq.dev with examples by ecosystem

## Open Questions

1. Should `.agentignore` support include-only mode (allowlist instead of denylist)?
2. Should category names be a fixed enum or free-form strings?
3. How should conflicts between `.agentignore` and agent-specific ignore files (`.cursorignore`) be handled?
4. Should the spec support conditional patterns based on agent capability (e.g., agents with vision can handle images)?
